## ТЕОРЕТИЧНИЙ БЛОК (0:40–2:30)

### Що таке Postman і навіщо він QA?

Postman — це інструмент для роботи з API. Він дозволяє:

*   Надсилати HTTP запити без написання коду
    
*   Зберігати запити в колекції (як папки з тест-кейсами)
    
*   Писати автоматичні перевірки результатів
    
*   Генерувати документацію та звіти
    

**Чому не просто браузер?**  
Браузер вміє тільки GET. Postman — GET, POST, PUT, PATCH, DELETE, і ще десяток методів. Плюс — бачимо повну відповідь, headers, статус код, час відповіді. Це наш основний інструмент на весь курс.

### Ghibli API — наш перший полігон

**Base URL:** `https://ghibliapi.vercel.app`

Доступні endpoints:

```plaintext
GET /films        → всі фільми
GET /films/:id    → один фільм за ID
GET /people       → всі персонажі
GET /people/:id   → один персонаж
GET /locations    → локації
GET /species      → види істот
GET /vehicles     → транспорт
```

Це REST API — кожен endpoint — це ресурс. Запам'ятай цю структуру, вона типова для більшості сучасних API.

### Крок 2: Знайомство з інтерфейсом (4:30–6:00)

> *\[Screencast: Postman відкритий, показуємо основні зони\]*

```plaintext
┌─────────────────────────────────────────────┐
│  Sidebar (колекції, history)  │  Workspace   │
│                               │              │
│  Collections                  │  [Method][URL]│
│  ├── My Workspace             │  Params      │
│  └── ...                      │  Headers     │
│                               │  Body        │
│                               │──────────────│
│                               │  Response    │
└─────────────────────────────────────────────┘
```

Ключові елементи:

*   **Method selector** (зліва від URL) — вибираємо GET, POST тощо
    
*   **URL bar** — адреса запиту
    
*   **Send** — надіслати запит
    
*   **Params / Headers / Body** — налаштування запиту
    
*   **Response area** (знизу) — відповідь сервера

### Крок 4: Запит на один фільм за ID (8:30–10:00)

> *\[Копіюємо id першого фільму з попередньої відповіді\]*

1.  URL: `https://ghibliapi.vercel.app/films/2baf70d1-42bb-4437-b551-e5fed5a87abe`
    
2.  **Send**
    

> *\[Показуємо: тепер відповідь — один об'єкт, не масив\]*

**Коментар:** "Бачиш різницю? `/films` — повертає масив усіх фільмів. `/films/:id` — повертає один конкретний об'єкт. Це базовий REST патерн який ти зустрінеш у кожному проєкті."

* * *

### Крок 5: Неіснуючий ресурс — 404 (10:00–11:00)

1.  URL: `https://ghibliapi.vercel.app/films/wrong-id-123`
    
2.  **Send**
    

> *\[Показуємо: 404 Not Found — червоний статус\]*

**Коментар:** "А ось так виглядає помилка. 404 — ресурс не знайдено. Саме це ми будемо перевіряти в наших тестах: що при правильному ID — 200, при неправильному — 404."

* * *

### Крок 6: Tabs у відповіді — що де шукати (11:00–12:00)

> *\[Показуємо всі вкладки Response area\]*

*   **Body** — дані відповіді (JSON, XML, HTML)
    
*   **Cookies** — cookies від сервера
    
*   **Headers** — заголовки відповіді (Content-Type, Date тощо)
    
*   **Test Results** — результати автоматичних тестів (поки порожньо — це у наступних уроках)
    

> *\[Показуємо: Pretty / Raw / Preview режими у Body\]*

**Pretty** — відформатований JSON (читабельно)  
**Raw** — сирий текст (як є)  
**Preview** — рендер HTML (для веб-відповідей)
